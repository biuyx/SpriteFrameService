# 视频跨入口幂等保护（2026-10-22）

用户授权补齐普通视频生成与一键流水线的跨入口幂等保护、补测试，仅在没有运行或排队任务时上线。不得进行真实付费测试或重提交已有任务。

## 最终行为

- 普通视频、批量视频与流水线start/resume共用短期提交锁及动作级活动任务检查。一个动作已有排队、运行或停止退出中的生成/流水线时，其他入口明确提示原任务，不再创建第二个任务；不同动作仍按现有视频5、本地1等预算调度。
- 浏览器为每次确认的操作保存request_id；并发点击合并，响应丢失、5xx或刷新后重试沿用编号，切换参数不丢旧请求凭据。收到成功响应后，下一次明确确认可生成新的版本。同一编号改变参数会被拒绝。普通视频和流水线的编号随JobStore持久化，历史淘汰或服务重启后仍返回原任务，不重放已结束、取消或失败记录。
- 旧客户端无编号时，同参数请求保守复用原任务。升级前已有生成历史且无可匹配请求编号时要求刷新页面重新确认，不擅自把旧请求作为新付费操作。
- 所有视频生成入口（包括MCP执行路径）在核心函数中原子检查并写入takes.json占位，再于供应商POST之前把提交意图记为unknown。索引原子替换并fsync；JSON损坏、未确认pending/running或未知提交都会阻止新生成。
- 已取得远端ID时，取消、轮询/下载异常保留原ID和待核对状态，通过现有reconcile只查回已有任务。明确远端终态失败或明确HTTP拒绝可在新确认后重新尝试；408、5xx、创建响应丢失/缺ID保留未知状态，不自动退款、重试POST或覆盖凭据。未知且没有远端ID时须先由管理员核对供应商，不提供强制重复生成捷径。
- 未确认的付费版本不能删除以绕过保护。已有成功/失败/上传视频和选中版本保持；不批量迁移旧记录，不改GPU、并发、内存、权限、额度或审批。
