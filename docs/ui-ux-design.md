# 客户端整体设计与 UI/UX 优化方案

配套：[视频生成接入](./video-generation-design.md) · [资产生命周期](./asset-lifecycle-design.md)

---

## 1. 现状评估（实测，1280×720）

### 1.1 空间账：一半屏幕给了不该看的东西

| 区域 | 尺寸 | 占比 |
| ---- | ---- | ---- |
| 侧栏 | 168×720 | 13% 宽 |
| 主工作区 | 645×438 | 50% 宽 |
| 右侧视频面板 | 467×438 | **36% 宽** |
| 底部帧管理 | 1112×240 | **33% 高**（无帧时同样占满） |

问题在于**右侧面板永远是源视频播放器**（除「视频抽帧」页外常驻）。
可是在「背景处理」页，用户要判断的是**抠图结果**；在「图像处理」页，要看的是
**缩放裁剪后的帧**。此刻放一个源视频播放器，等于把 36% 的屏幕用在无关内容上，
而真正该放大看的帧被挤在底部 240px 的横条里。

主工作区实际可用高度只有 **438px**——在 1366×768 这类办公本上会更局促。

### 1.2 信息架构：是工具箱，不是流水线

侧栏 7 项：`视频抽帧 / 动作分析 / 背景处理 / 图像处理 / 魔棒编辑 / 导出 / 历史回退`

这是**按功能模块**排的，不是按**实际工作顺序**。新用户看不出：

- 该从哪开始、下一步是什么
- 「动作分析」是必经步骤还是可选优化（实际是可选）
- 「历史回退」不是一个工作阶段，却和工作阶段并列
- 当前会话进行到哪一步了，完全没有指示

接下来还要加「视频生成」「资产库」「存储」——**平铺就是 10 项**，只会更糊涂。

### 1.3 选择模型是隐式的，且容易误操作

后端 `require_indices()` 的规则是：**指定索引 → 选中帧 → 全部帧**。
即「没选中任何帧时，操作作用于全部帧」。

界面上只在按钮里写「批量抠图（全部 帧）」这样一行小字。用户很容易在
以为只处理选中帧的情况下，对上百帧发起了不可逆的批量操作。

### 1.4 参数陷阱没有任何防护

`Alpha阈值 / 腐蚀 / 羽化` 是三个裸 number input。而实测结论是：

- **Alpha 阈值填 1~50 比填 0 更糟**（把淡白边缘提升为完全不透明，边缘环亮度 124 → 242）
- 羽化会加宽过渡带，做精灵图基本不该开

界面对此零提示，用户只能靠试错和事后翻文档。

### 1.5 模型推荐与实测相悖

下拉里 `BRIA RMBG 2.0 (推荐)`——「推荐」二字写死在后端 `AI_MODEL_INFO` 里。
但实测（你的真实素材）：

| 模型 | 边缘环亮度 | 单帧耗时 |
| ---- | ---- | ---- |
| bria-rmbg-2.0 | 23.3 | **8.7s** |
| isnet-anime | 29.6 | **0.4s** |

界面把**慢 22 倍、质量仅好一点点**的模型标为推荐，且没有任何速度提示。

### 1.6 其他

- 会话只有 12 位十六进制（`81a6680d`），认不出谁是谁
- 撤销要专门切到「历史回退」页，没有全局 Ctrl+Z
- 帧管理面板在无帧时仍占满 240px
- 长任务运行时缺少「可以去干别的」的明确引导

## 2. 信息架构重构：从工具箱到流水线

### 2.1 分组导航

把 10 个入口按**性质**分三组，而不是平铺：

```
制作                     ← 线性流程，带进度指示
  ① 素材        生成视频 / 上传视频 / 版本(take)管理
  ② 抽帧        时间范围、帧率、抽取
  ③ 精修        去相似 · 抠图 · 描边 · 缩放裁剪 · 魔棒   ← 合并为一页，标签页切换
  ④ 导出        精灵图 / GIF / WebP / Godot

资产
  资产库        跨会话的交付物，缩略图墙 + 血统
  存储          占用分析、分级回收

（会话切换器与撤销提到顶栏，不占导航位）
```

要点：

- **①②③④ 是线性阶段**，用带序号的步骤条呈现，每步显示完成状态
  （未开始 / 进行中 / 已完成 + 关键数字，如「③ 精修 · 122 帧已抠图」）
- 未满足前置条件的步骤置灰并说明原因（「请先在 ② 抽帧 中提取帧」）
- **「精修」把现有 4 个页面合并**：动作分析、背景处理、图像处理、魔棒编辑
  本质都是「对帧做处理」，共享同一套帧预览区，用二级标签切换即可，
  省掉 3 次整页跳转与重新加载
- **「历史回退」不再是导航项**——它是全局能力，提到顶栏（撤销按钮 + 历史抽屉）

### 2.2 每步完成后给出「下一步」

每个阶段页底部固定一条**行动条**：左侧是本步结果摘要，右侧是主按钮直达下一步。

```
[✓] 已抽取 122 帧，其中 79 帧被标记为相似          [ 去精修 → ]
```

这是把「用户得自己知道流程」变成「界面带着走」的最小改动。

## 3. 布局重构

### 3.1 右侧面板改为「上下文预览」

不再永远是源视频，而是**跟随当前阶段切换内容**：

| 阶段 | 右侧面板内容 |
| ---- | ---- |
| ① 素材 | 视频播放器 + take 版本列表 |
| ② 抽帧 | 视频播放器 + 时间轴刻度（与抽帧范围联动） |
| ③ 精修 | **当前帧大图**（棋盘格背景）+ 处理前/后对比滑块 |
| ④ 导出 | 精灵图排布预览 + 尺寸/体积估算 |

「精修」阶段的**前后对比滑块**是关键：抠图和图像处理的效果判断依赖细节比对，
现在只能靠帧管理里的小缩略图，看不清边缘。

### 3.2 面板可折叠，空间可回收

- 右侧面板加折叠按钮，折叠后主工作区回到 100% 宽
- 帧管理无帧时自动收为一条 32px 提示条（现在无帧也占 240px）
- 记住用户对各面板尺寸的调整（localStorage）

### 3.3 帧管理增强

- 缩略图上叠加状态徽标：已抠图 / 已分析 / 补帧 / 已选中
- 支持框选、Shift 连选、Ctrl 点选
- 顶部常驻一行：`共 122 帧 · 已选 0 · 已抠图 122`

## 4. 关键交互优化

### 4.1 选择范围显式化（优先级最高）

所有批量操作按钮统一改为**明确说明作用域**，并在作用于全部帧时二次确认：

```
未选中任何帧：  [ 抠图 · 作用于全部 122 帧 ]   ← 点击后弹确认
已选中 20 帧：  [ 抠图 · 作用于选中 20 帧 ]    ← 直接执行
```

顶部同时常驻作用域指示器，避免「以为只处理选中帧」的误操作。

### 4.2 参数从「裸输入框」改为「预设 + 可展开高级」

背景处理默认只给三个预设，把实测最优解固化下来：

```
○ 精灵图推荐   isnet-anime · 阈值128 · 腐蚀1 · 羽化0      ← 默认
○ 极致质量     bria-rmbg-2.0 · 阈值128 · 腐蚀1（慢 20 倍）
○ 快速预览     silueta · 阈值0 · 腐蚀0
▸ 高级参数（展开后才是现在的三个输入框）
```

高级参数区对已知陷阱做**内联提示**，而不是等用户踩：

- Alpha 阈值滑到 1~50 时，输入框下方直接显示橙色提示
  「该区间会把半透明边缘提升为完全不透明，白边反而更重；建议 0 或 ≥128」
- 羽化 > 0 时提示「会加宽过渡带，精灵图通常不需要」

### 4.3 模型选择带上真实代价

下拉项改为展示实测数据，并把「推荐」给对：

```
ISNet Anime (动漫)      边缘 ★★★★  速度 0.4s/帧   ← 推荐
BRIA RMBG 2.0           边缘 ★★★★★ 速度 8.7s/帧
Silueta (轮廓)          边缘 ★★☆   速度 0.3s/帧
U2Net (通用)            边缘 ★★☆   速度 0.1s/帧
U2Net Human (人像)      真人专用，卡通角色不适用
```

选中慢速模型时，按帧数估算总耗时并提示（「122 帧约需 18 分钟」）。

### 4.4 全局撤销

- 顶栏放撤销按钮 + `Ctrl+Z` 快捷键，直接回退上一步
- 点击旁边的箭头展开历史抽屉（现在「历史回退」页的内容）
- 每步显示可回退性与快照占用

### 4.5 长任务的非阻塞体验

生成视频要几分钟，抠图上百帧要几分钟。现在只有一个浮层任务条。

- 任务卡片显示：阶段、进度、**预计剩余**、可否取消
- 明确提示「可切换到其他页面，完成后会通知」
- 同会话任务串行（后端已实现），队列中的任务显示「排队中，前面还有 N 个」
- 完成时 toast + 任务卡高亮，失败时给出**可操作的**错误
  （现在的错误是 `RuntimeError: xxx` 这类原始信息，应翻译成用户语言 + 建议动作）

## 5. 新增页面的设计要点

### 5.1 ① 素材（含视频生成）

- 上方是生成表单（未配置 API Key 时整块置灰并说明去哪配）
- 下方是 **take 版本墙**：封面 + 参数摘要 + 状态 + 成本
- 每个 take 卡片：`用这个` / `以此为首帧再生成` / `删除`
- 「以此为首帧再生成」直接把选中帧喂回生成表单——这是生成并入服务后最有价值的动作
- 生成中的 take 显示占位卡 + 进度，不阻塞其他操作

### 5.2 资产库

- 缩略图墙，按标签/时间/来源会话筛选
- 卡片点开：预览、血统（recipe）、下载、一键复现
- 「血统」用可读的步骤列表呈现，而不是裸 JSON

### 5.3 存储

- 顶部：总占用 / 磁盘剩余 / 可回收空间（三个数字 + 一条堆叠条）
- 按会话列出：名称、状态、占用、最后访问
- 回收前**列出将删除什么、能否重建、怎么重建**，确认后执行
- 永不自动删除源料与交付物（见资产生命周期方案）

## 6. 视觉与细节

现有暗色主题（VS Code 风格）基调没问题，token 也已抽出，主要缺的是**层次**：

- 补 `--bg-elevated`、`--radius`、`--space-*`、`--shadow` 等 token，
  当前只有颜色 token，间距和圆角散落在各组件里
- 主按钮（执行操作）与次按钮（辅助）视觉分级现在几乎一样，需要拉开
- 危险操作（删除帧、删除会话、清空）统一红色边框 + 二次确认
- 空状态统一：图标 + 一句说明 + 一个主行动按钮（现在多是一行灰字）
- 焦点态 `:focus-visible` 描边（当前键盘操作几乎不可见）
- 数字输入框统一宽度与对齐（现在宽度不一）

## 7. 分阶段实施

按「投入产出比」排序，每阶段独立可交付：

**第一阶段 · 低成本高收益（不动架构）**

1. 选择范围显式化 + 全量操作二次确认 —— 防误操作，最高优先级
2. 参数预设 + 陷阱内联提示 + 模型标注真实速度 —— 把实测结论固化进界面
3. 帧管理无帧时自动收起、右侧面板可折叠 —— 立刻拿回屏幕空间
4. 错误信息翻译成用户语言

**第二阶段 · 信息架构**

5. 导航分组 + 步骤条 + 「下一步」行动条
6. 「精修」合并四页为二级标签
7. 撤销提到全局

**第三阶段 · 随新功能落地**

8. 右侧面板上下文化（含前后对比滑块）
9. ① 素材页（视频生成 + take 版本墙）
10. 资产库、存储页

**第四阶段 · 打磨**

11. 设计 token 补全、空状态、焦点态、快捷键

第一阶段完全不依赖后端改动，可以立即做，且直接消化掉本文档 §1.3~1.5 三个实测问题。

## 8. 待决策

| 项 | 说明 |
| ---- | ---- |
| **是否合并「精修」四页** | 合并后交互更连贯、少 3 次跳转，但单页复杂度上升，且四个页面现有代码要重构成标签页。若想稳妥，可先只做导航分组，保持四个页面独立。 |
| **是否引入前端路由** | 现在用 `nav.js` 一个 ref 管理 tab，加了分组和二级标签后会变复杂，可能需要 vue-router。但那会给绿色包增加依赖，且当前无刷新恢复的需求。建议先不引入，用嵌套状态顶住。 |
| **移动端/小屏** | 当前布局在 1366×768 已经局促。是否需要响应式降级（右侧面板自动折叠）？还是明确只支持 ≥1440 宽？ |
