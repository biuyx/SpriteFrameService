# 精灵库第一阶段：项目、类型与多级分类

## 使用方式

精灵库顶栏选择项目，左侧分类树支持多级目录和展开/折叠，点击目录可查看全部后代类型的角色。类型是目录下的叶节点；角色通过稳定的 project_id、sprite_type_id 关联，不依赖名称或磁盘路径。原 tags 保留为标签，支持继续筛选与搜索。

「管理项目 / 分类 / 类型」中先建立项目，再建立分类目录和类型。类型可保存默认参考分组、固定首帧集、逐项共享参考。默认配置只在新建时复制，既有角色不会自动升级。完整动作骨架仍通过现有样板角色复制，本阶段不实现独立模板方案版本、工艺升级或项目权限隔离。

在类型内新建时自动带入归属，可选择同项目样板角色；完整副本继承原归属。复制前检查目标类型与原参考动作的兼容性，避免冲突后留下半成品。

旧角色不会自动改写：缺失归属或项目 ID 不可解析时，在「待归类」中可找到；有效项目但无可解析类型的角色在「未指定类型」中可找到。勾选角色→归类所选→选择项目与类型→预览→确认。预览包含档案版本指纹，保存时复查全部角色和目标归属；不会改原标签、素材路径、立绘、参考绑定、动作或工艺，失败回滚当轮档案写入。跨参考分组冲突需明确处理，不以类型默认值覆盖原角色。

批量目录导入的预览与执行均按项目及类型匹配同名角色；多个同名候选时不自动选取。原 project 字符串仍是旧标签字段，新增 project_id / sprite_type_id 才是稳定归属。原项目 zip 的标签筛选语义保留；本阶段没有跨服务器合并分类目录的功能，不可解析的归属可重新明确归类。

## 数据与接口

- `data_dir/library_catalog.json`：version=1，projects/categories/types；首次读取不创建文件，无启动迁移。写入使用进程内互斥和临时文件原子替换，损坏时明确拒绝、不覆盖。
- 项目、分类、类型 ID 分别为 pr_ / cat_ / st_。项目内目录与类型均可独立改名；目录不能循环或跨项目移动。仍有子项或角色引用时禁止删除。
- 角色 sprite.json 新增可空 project_id、sprite_type_id，旧文件缺字段仍合法；素材继续位于原 sprites/{sprite_id}/actions/{action_id}。
- GET `/api/library`；POST/PATCH/DELETE `/api/library/{projects|categories|types}`；POST `/api/library/assignment/{preview|apply}`。沿用管理员认证，AI 密钥仍仅能调用 MCP，未增加密钥权限或工具数量。
- 原精灵 REST 新建/修改支持归属字段；归属调整与目录改名不改变生成计划引用。MCP 角色列表/概览增加归属 ID，重复名字仍要求明确角色 ID。
- 类型参考分组已有使用者时不直接切换；尚未配置默认分组的类型可在不与现有绑定冲突时补齐默认值。默认首帧集必须存在且同组。
