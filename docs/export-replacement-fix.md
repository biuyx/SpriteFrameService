## 原因和修复

逐动作导出之前在既有 `exports/<name>` 内覆盖写文件。帧数缩短、改选部分帧或切换格式时，上一版多出的帧和附件不会被删除，下载目录可能混合两版素材；原 `.incomplete` 仅保护失败导出，没有解决成功目录重导出的残留。

普通导出、流水线和 MCP 共用的 `run_export` 改为在动作目录下的独立暂存目录完整生成；产物非空且未取消后整体替换同名导出目录。暂存目录不在可下载列表中，失败、空结果、取消均保留旧导出；替换失败恢复旧目录，连回滚也失败时保留隐藏备份供恢复。重新导出不合并上一版任何文件，不修改原始/抠图帧或 `frames.json`，不同导出名保留各自版本。旧版 `.incomplete` 目录重试成功时由新完整目录替换。返回的主文件名、附件信息和目录仍指向正式位置。

发布是同文件系统的目录重命名，旧目录移走与新目录放入之间有极短不可用窗口；进程在该窗口异常退出时，旧目录留在动作目录 `.export-previous-*` 可人工恢复，不把半成品公开。未改动任务准入、资源配置、权限、GPU或付费逻辑。
